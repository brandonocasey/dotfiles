## General

- Verify factual claims against code or data before implementing. If a wrong claim changes the result, show the evidence and ask whether to proceed or take the alternative. If it does not, correct it in one line and proceed. For a merely better approach, name it and its cost, then do as asked.
- Build what I asked, as worded; where I say always, every, or same, build it without conditions. Keep approved plans and defaults as approved. Add no condition, threshold, scope change, or visual change I did not state, even when it is cheap to undo; name it as an option instead. This overrides taking recommended options without asking. Before reporting done, check the result against each requirement I stated.
- Before irreversible work, show a read-only preview of the scope and what cannot be restored. Get approval unless that scope is already approved.
- Ask before destructive work, unapproved outward actions, credentials, or using my device. Ask before out-of-scope work unless a follow-up rule covers it. Skill gates and required approvals still apply. When you add, move, or merge anything that can start such an action (skill, hook, permission rule, config option), keep its gate in settings or code that the repository and the model cannot change, not in prose alone; if no such place exists, tell me. Check every route to it: model invocation, other skills, repository or symlinked config, agent-editable settings.
- Run commands yourself; hand me one only when you cannot run it (interactive login, blocked action). Never ask me to confirm work I requested. Before handing me a command or script, test it: check syntax (`sh -n`), that tools and paths exist, and run any safe part.
- Never search `env`, `~/.netrc`, or config for credentials. Only secret-leak scans of tracked or unignored repository files are exempt; report matches as `path:line` with values redacted.
- Put output in chat or where I asked, in the format I asked. Use hosted-document skills or write to hosted docs (such as Google Docs, Claude Docs, Confluence, or artifacts) only when I name one or one is already in use; a skill's default is not permission.
- Never put Claude session or artifact links (claude.ai/artifact, claude.ai/code, session URLs) in public-facing text: MR/PR titles and descriptions, comments, commits, docs, issues, or release notes. Attach the content itself (images, logs, text) instead.
- Before calling a change done or working, run it where I meet it: the same program, client, device, shell, and starting state, such as a fresh session, a reload of a running one, or the real service. Check the effect itself, such as the drawn screen, the purged URL, or the posted message. Tests, headless CLI or piped runs, status codes, mocks, and fake harnesses are proxies, not proof. Load `ux-verify` first for UI and other user-facing output. In the report, say where you saw it work. Approval rules still apply: ask before posting, purging, or using my device; sub-agents never start headed browsers or real Safari. If you cannot reach that surface yourself, write `unverified: <surface>` and what you checked instead. Internal refactors with passing tests and text-only edits need only a diff check.
- Never weaken/skip/remove tests, add lint/type suppressions, or edit test/lint/type config without consent. Intended behavior changes may update tests; disclose them.
- Waiting (Claude Code's hook moves most foreground waits to the background, but a call that starts with `sleep N`, N >= 25, is rejected before the hook runs, so never lead with `sleep`):
  - `sleep` of 20s+, a loop that sleeps, `sleep N; cat log`, `agt wait`, `agt ci wait`, `gh run watch`, or a long sub-agent call in the foreground → run it in the background (Claude Code: `run_in_background: true`; jobs write a log file), then stop until its exit notification.
  - Commands likely to take over ~20s (test suites, builds, browser runs) start in the background; short commands stay foreground.
  - `pkill`, `killall`, `kill $(pgrep …)`, or `pgrep … | xargs kill` by name also stops other sessions' processes → `kill` the PID you saved at start, or `pkill -F <pidfile>`; for one you did not start, list it with `pgrep -fl '[n]ame'`, then kill it by number in a separate call.
  - Use `pgrep -f '[n]ame'` in a call with no other copy of the name (no `cd` into or `cat` of its path).
  - When stopping to wait, say what you are waiting on and the expected duration.
- Use `agent-probe` for headless usage or A/B probes. In other `claude -p` runs, keep `ToolSearch` in any `--tools` list. When tool search is off (`ENABLE_TOOL_SEARCH=false` in env or settings, a custom `ANTHROPIC_BASE_URL`, or ToolSearch denied), add `--strict-mcp-config`. Without these, every connector tool is sent in full: about 600k tokens per call.
- Each tool call re-sends all context, so use few calls. Combine independent commands; search the whole scope in one call, never file by file. For a named symbol, find references with `rg -n '\bName\b'` and the definition with `rg -n '(fn|struct|enum|trait|type|const|class|interface) Name\b'`. Then read only those ranges, once, all known ranges in one call; go one at a time only when the next depends on it. Still read all needed context: the whole function, its callers, and the contracts it depends on. Chain dependent steps whose output you need not inspect into the call that uses them with `&&`: `mkdir`, `cp`, `rm`, file writes, and `git add` before the command that needs them. Use absolute paths or `git -C` rather than a leading `cd`, which triggers permission checks in compound commands.
- Use `rg` for code and text, also on piped output (`grep` only where `rg` is missing). Use `ast-grep` only when text matches would be ambiguous, with output trimmed to file:line (`--json=stream | jq`). In `rg`, `-r` means replace; add `--hidden` for dotfiles.
- Cap long output with quiet flags, `head`, `tail`, or `rg`. Start diffs with `git diff --stat` or `git show --stat`, then diff only needed paths.
- When compacting, keep the full list of changed files, the test and check commands, and scratch file paths.
- Read ranges with `sed -n` or `rg`; the file-read tool's line-numbered output costs more tokens. In Claude Code, Bash output over 6,000 characters (`BASH_MAX_OUTPUT_LENGTH`) is saved to a file and needs a second read, so use the file-read tool for skill files, longer reads, and files you will edit (Edit and Write reject files seen only through Bash). Elsewhere, use `cat` to load whole skill files; heredocs are fine. Read a code file over about 200 lines whole only when you need most of it.
- Change existing files with targeted edits; rewrite a whole file only when it is new or almost entirely replaced.
- zsh: no words starting with `=` (use `printf '--- %s\n'`); write `${B}:refs/...` and quote refspecs.
- Delete your own task dir at task end; `agt cleanup` handles leftovers. Delete with literal paths or `find <dir> -delete`, never `rm` on a variable or glob.
- Run `chezmoi apply/add/re-add` as a standalone command, never chained. Run MR/PR approve and merge as separate commands. Do not append `; echo rc=$?` to commands.
- Edit a chezmoi-managed file (most under `~/.claude`, `~/.codex`, `~/.config`, and `~/.local/bin`) through the source that `chezmoi source-path <file>` prints. Before editing a source, read `~/.claude/rules/chezmoi-source.md` unless it is in context, and for a hook or guard also `matchers-and-guards.md` there.
- To find a past session, run `agt sessions search` first.
- If a stop-hook objection repeats and needs my decision, reply with the decision needed and call no tools.

## Directories

Prefer XDG cache/state roots when set, otherwise `~/.cache` and `~/.local/state`, including Windows. Keep fixed paths a tool requires; use `/tmp` only when a tool needs it or I ask.

- Scratch: `<worktree>/.cache/agents/scratch/<task>/` of the worktree the task works on, even when the session runs in the main checkout or elsewhere, so removing that worktree removes it; only for tasks tied to no worktree, `$TMPDIR` or the harness scratchpad when under the cache root, else `~/.cache/agents/scratch/<task>/`.
- Task list (main sessions; sub-agents skip): keep a running `TODO.md` under `agents/output/<task>/` in the XDG cache root. Add an item every time I ask for something or something comes up. Write incomplete items as `- [ ]` and complete ones as `- [x]`. Add a one-line note to items dropped or waiting on my decision. Keep `- [ ] Cleanup & task end` as the last item. I may edit it; reread it before acting and treat my edits as instructions. Before reporting done, check every item against the work; check the last item once the task dir is deleted. Keep the file after the task ends.
- Per-worktree build output (Cargo `--target-dir`, Xcode `-derivedDataPath`, test results) set by a flag goes under `<worktree>/.cache/agents/`. Use installed toolchains (mise, Homebrew) and shared package caches; never download an SDK or toolchain copy into a worktree.
- Backups before overwrite, force-removal, or migration: `~/.local/state/agents/backups/<repo>/<YYYYMMDD-HHMM>-<reason>/`; preserve relative paths, never auto-prune, report the path.

## Skills own the detail

Load relevant skills and rule files whole, once. Read each action's rule files in one parallel batch, only when the task reaches that action. Reread only after changes, lost context, or a specific detail check.

- Skill paths in global rules, and unlisted `<name>/SKILL.md` skills, are under `~/.config/agents/skills/`.
- Skill commands use POSIX sh; on Windows use Git Bash, else PowerShell. Run skill Git commands with every flag shown.
- Before servers/resources and at cleanup: `host-preflight/references/task-resources.md`. iOS Simulator: one per worktree, per its **iOS Simulator** section.
- Before Git work: `shared/git-policy.md`; it owns Git consent, commits, remote-state verification, conflict resolution, and MR/PR updates. Before branch work, including sequential tasks, also read `worktree/SKILL.md`, `worktree/references/create.md`, and `shared/default-branch.md`; add `worktree/references/prepare.md` before checks or commits. Create and set up worktrees yourself with `agt worktree create <branch>` (add `--prepare` per `worktree/references/prepare.md`), never through a `cheap` agent. Never switch branches in the main checkout. An initial implementation (new project, no repo yet) needs no worktree, only a creation location: use the one given, else ask.
